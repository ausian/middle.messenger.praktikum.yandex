# y.messenger

Современный веб-мессенджер на TypeScript, Handlebars и Vite. Приложение реализует SPA-роутинг без крупных фреймворков, поддерживает прямые переходы по ссылкам и поставляется с сервером на Express для раздачи статических файлов.

## Основные возможности
- SPA-роутер на History API с fallback-страницами и поддержкой прямых переходов.
- Реальные чаты через WebSocket: загрузка истории, пинг соединения и автоматическое переподключение.
- Управление чатами: создание, добавление и удаление участников, обновление аватаров.
- Развитая компонентная система на Handlebars с модульной версткой и переиспользуемыми блоками.
- Формы с клиентской валидацией, подробными ошибками и UX-обработкой состояний загрузки.
- Vite для разработки с HMR; production-сборка раздается Express-сервером.
- Современный стек CSS на PostCSS (postcss-nested, autoprefixer, postcss-preset-env) и Stylelint.

## Функциональные сценарии
- Регистрация и авторизация с автоматическим восстановлением сессии и выходом из аккаунта.
- Просмотр списка чатов, выбор активного чата и синхронизация состояния через стор.
- Обмен сообщениями в реальном времени с WebSocket-токенами Практикума.
- Управление участниками: поиск по логину/нику и обновление состава чата.
- Настройка профиля: изменение данных, пароля и аватара с всплывающими уведомлениями.
- Системные страницы для 404 и 500 с корректной работой роутера.

## Начало работы

### Требования
- Node.js версии 20.19.0 или новее
- npm 10+

### Установка
```bash
npm install
```

Запуск проекта во время разработки выполняется одной командой:
```bash
npm run dev
```

По умолчанию фронтенд обращается к API Практикума напрямую. Чтобы локальная разработка обходила ограничения CORS, создайте файл `.env.local` (либо используйте любую `.env`‑конфигурацию Vite) со значением:

```
VITE_API_BASE_URL=/api/v2/
```

Vite автоматически применит проксирование `/api` на `https://ya-praktikum.tech` (см. `vite.config.js`), а приложение продолжит работать с базовым URL без изменений для production-сборки.

### Скрипты npm
| Команда | Назначение |
| --- | --- |
| `npm run dev` | Запуск development-сервера Vite с HMR. |
| `npm run build` | Сборка production-версии в `dist/`. |
| `npm run preview` | Локальный предпросмотр собранного бандла. |
| `npm run start` | Сборка и запуск Express-сервера (`server.cjs`) для production-режима. |
| `npm run lint` | Проверка TypeScript/JavaScript-части ESLint. |
| `npm run lint:fix` | ESLint с автоматическим исправлением. |
| `npm run lint:css` | Проверка стилей Stylelint. |
| `npm run lint:fix:css` | Stylelint с автоисправлениями. |

## Структура проекта
```
├── src/
│   ├── App.ts             # Точка входа приложения и инициализация роутов
│   ├── assets/            # Статические данные и mock-и
│   ├── components/        # UI-компоненты (atoms, molecules, organisms, layouts)
│   ├── framework/         # Мини-фреймворк: Block, EventBus и др. инфраструктура
│   ├── helpers/           # Вспомогательные функции и Handlebars-хелперы
│   ├── pages/             # Шаблоны страниц и их контейнеры
│   ├── styles/            # Глобальные стили и переменные
│   └── utils/             # Утилиты (валидация форм, HTTPTransport, парсеры)
├── server.cjs             # Express-сервер для продакшн-сборки
├── tsconfig.json          # Настройки компилятора TypeScript
├── vite.config.js         # Конфигурация Vite
└── postcss.config.js      # Конвейер PostCSS
```

### Ключевые модули
- `src/framework/Block.ts` — базовый класс для того, чтобы компоненты обладали жизненным циклом и реактивностью.
- `src/framework/Router.ts` и `Route.ts` — собственный History API роутер с fallback-маршрутом.
- `src/framework/Store.ts` — EventBus-стор с подписками и безопасным обновлением по строковым путям.
- `src/api/BaseAPI.ts` + `src/utils/HTTPTransport.ts` — thin-слой над fetch с типами, обработкой ошибок и поддержкой FormData.
- `src/controllers/*` — бизнес-логика (авторизация, чаты, пользователи) отделена от компонентов.
- `src/utils/popupService.ts` — единая система всплывающих уведомлений для UX-обратной связи.

## Кодстайл и проверка качества
- Проект использует строгий `tsconfig` со включённым `strict` и `noImplicitAny`.
- ESLint настроен на базу Airbnb для TypeScript и Prettier-совместимость.
- Stylelint проверяет CSS/PCSS-файлы и поддерживает автоисправления.
- Перед созданием pull request рекомендуется запускать `npm run lint` и `npm run lint:css`.
